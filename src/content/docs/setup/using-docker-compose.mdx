Astro Theme Pure 提供了 Docker Compose 工作流，用于在隔离的 Bun 容器中进行开发、构建、预览和内容创建。这使你无需在主机上安装 Bun 及其依赖，也不必直接在主机上运行相关工具，即可在 Docker 内完成这些工作流。

<Aside type='tip'>
  如需手动使用 Docker 构建，请参阅 [Astro：使用 Docker 构建你的 Astro 网站](https://docs.astro.build/en/recipes/docker/)。
</Aside>

## 环境要求

- [Docker Desktop](https://docs.docker.com/get-started/get-docker/)，需支持 [Docker Compose](https://docs.docker.com/compose/install)。

验证你的安装：

```shell
docker --version
docker compose version
```

## 工作原理

随附的 Docker 环境使用：

- **Bun**，基于官方 `oven/bun:debian` 镜像
- 由仓库 `Dockerfile` 构建的共享 Docker 镜像
- Compose profiles 以运行特定的工作流
- 用于构建产物和依赖的命名 Docker 卷

该 Docker 镜像：

- 通过 `bun install --frozen-lockfile` 安装项目依赖
- 禁用 Astro 遥测
- 暴露端口 `4321`
- 使用 `/web` 作为工作目录

所有服务复用同一镜像，仅在选中对应 profile 时才会启动。

## 可用的 profiles

每个工作流通过一个 Docker Compose profile 暴露。选择与你想要执行的任务对应的 profile：

| Profile   | 作用                                                                                                                            |
| --------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `build`   | 在容器内运行 `astro build`，并将输出复制到本地 `./dist` 目录。                                                                   |
| `dev`     | 在 http://localhost:4321 启动 Astro 开发服务器，源文件以 bind-mount 方式挂载，编辑后无需重建镜像即可立即生效。                     |
| `preview` | 先运行 `build` profile，构建完成后通过 `astro preview` 在 http://localhost:4321 提供生产构建的服务。                              |
| `new`     | 运行 `astro-pure new` 脚手架创建新文章，运行结束后不会留下持续运行的容器。                                                        |

## 生产构建

生成生产构建：

```shell
docker compose --profile build up --build
```

构建过程：

1. 运行 `bun run build`
2. 在容器内创建 Astro 生产输出
3. 将生成的文件复制到本地 `./dist` 目录

构建完成后，生成的站点位于：

```text
./dist
```

构建容器在完成后会自动退出。

## 重建 Docker 镜像

`--build` 标志会强制 Docker Compose 在启动服务前重建镜像。

在以下情况使用它：

- 更新项目依赖
- 修改 `package.json`
- 更改 `Dockerfile`
- 切换到带有依赖变更的分支

示例：

```shell
docker compose --profile dev up --build
```

<Aside type='tip'>
  再次运行 `--build` 并不一定会从头重建每一层。Docker 会尽可能复用缓存层，因此未变更的依赖和其他构建步骤仍可被缓存。
</Aside>

## 开发

启动 Astro 开发服务器：

```shell
docker compose --profile dev up --build
```

站点将可通过以下地址访问：

```text
http://localhost:4321
```

### 热重载

你的项目目录会直接挂载到容器中：

```yaml
- .:/web
```

这意味着源文件的变更会立即在容器内可见，从而让 Astro 开发服务器自动进行热重载。

项目依赖存储在专用的 Docker 卷中：

```yaml
- node_modules:/web/node_modules
```

这样可以避免容器管理的依赖与任何本地环境之间的冲突。

如需停止开发服务器，请按 <kbd>Ctrl</kbd> + <kbd>C</kbd>。

## 预览生产构建

构建并提供生产输出的服务：

```shell
docker compose --profile preview up --build
```

预览工作流：

1. 执行 `build` 服务
2. 通过 Docker 卷共享生成的文件
3. 启动 Astro Preview

生产预览可通过以下地址访问：

```text
http://localhost:4321
```

这有助于验证比开发服务器更接近生产部署的行为。

## 创建文章

Astro Theme Pure 提供了一个脚手架创建新文章的命令，无需在本地安装依赖即可运行。

创建新文章：

```shell
docker compose --profile new run --rm new
```

这会执行：

```shell
bun run pure new
```

该容器只挂载内容目录：

```yaml
- ./src/content:/web/src/content
```

生成的内容会直接写入你的项目。

`--rm` 标志会在命令完成后自动删除临时容器。

## 清理

停止容器并移除 Compose 资源：

```shell
docker compose down
```

同时移除关联的卷：

```shell
docker compose down --volumes
```

这会删除存储在 Docker 卷中的缓存构建输出和已安装的依赖。
